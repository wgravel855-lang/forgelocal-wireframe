Quantization and formats

What Q4_K_M means, and why the same model comes in six sizes.

4 min read · Describes the behaviour this build defines

Why models come in several sizes

A model is trained at 16 bits per weight. Storing it that way makes it too large for most consumer graphics cards, so it is quantized: the weights are stored at fewer bits, with a scheme that keeps the parts that matter most at higher precision. The result is a much smaller file that is nearly as good.

That is why one model appears as several downloads. They are the same trained model at different precision, not different models.

Reading a quantization name

Q4_K_M
|  |  |
|  |  +-- size within the family: S small, M medium, L large
|  +----- K-quant, a mixed-precision scheme
+-------- 4 bits per weight on average
Q8_0
8 bits. Almost indistinguishable from the original, and about twice the size of Q4.
Q6_K
6 bits. A very small quality cost for a meaningful size saving.
Q5_K_M
5 bits. A reasonable middle if Q4 feels lossy on your work.
Q4_K_M
4 bits. The usual default. Best size-to-quality ratio for coding work.
Q3_K_M
3 bits. Noticeably weaker. Worth it only to make a larger model fit at all.
Q2_K
2 bits. Degraded enough that a smaller model at Q4 is normally the better trade.

The practical rule: prefer a larger model at Q4_K_M over a smaller model at Q8. Below Q4 the losses start to show up as broken syntax and forgotten instructions, which is exactly where coding work is sensitive.

Formats

This build uses GGUF files run by llama.cpp. GGUF is a single-file format that carries the weights and the metadata the runtime needs, which is what makes a model one download rather than a directory of parts.

Weights come from the publisher, not from ForgeLocal. Every model page links its source repository and pins a revision, so an upstream change cannot silently alter what is installed on your disk.
